# Старт цикла разработки

Готовит чистый цикл и собирает в него пункты. **Ничего не анализирует, не кодит, не рисует макеты** — только фетчит, заводит ветку и файл, записывает.

## Шаги при запуске скилла
1. `git fetch origin`.
2. `git checkout main && git pull` — ветка цикла растёт от свежего main.
3. Определить номер цикла `N`: наибольший из существующих `docs/cycles/cycle-*.md` и веток `cycle-*` плюс 1. (Исторически циклы шли как `dev-N`/`docs/TZ.md`; новые — `cycle-N`/`docs/cycles/`.)
4. `git checkout -b cycle-N`.
5. Создать `docs/cycles/cycle-N.md` по шаблону ниже. Прошлые циклы лежат в той же папке — они и есть архив, отдельная `docs/archive/` больше не нужна.
6. Сказать Максиму: цикл `N` открыт на ветке `cycle-N`, кидай пункты; когда готов — «запускай полный цикл» (скилл `cycle-run`).

## Режим сбора (пока идёт цикл-сбор)
- Каждый присланный баг/идею/доработку записывай в файл отдельным пунктом. Код не трогается.
- **ID сквозные, не переиспользуются:** `B-n` — ошибка, `F-n` — хотелка, `U-n` — удобство/оптимизация, `I-n` — идея на будущее. Продолжай нумерацию от максимума по всем прошлым циклам (`docs/cycles/*` и `docs/archive/TZ-*`).
- Идеи, которые не берутся в этот цикл, идут в `docs/ROADMAP.md` (`I-n`), не в файл цикла.
- Приоритет: `P1` мешает пользоваться, `P2` заметно неудобно, `P3` приятно бы.
- Правки файла цикла коммить локально в `cycle-N`, **не пушь**, пока цикл не запущен (`cycle-run` сам решит, когда пушить).

## Шаблон `docs/cycles/cycle-N.md`
```markdown
# Цикл N

Живой документ сбора. Баги, неудобства, идеи — отдельными пунктами. Ничего не анализируется, пока не запущен `cycle-run`.

**Статус:** сбор. **Ветка:** `cycle-N` (от `main`, <дата>).

## Как читать
- ID: `B-n` ошибка, `F-n` хотелка, `U-n` удобство, `I-n` идея. Нумерация сквозная.
- Статус: `новое` → `разобрано` → `в работе` → `готово` (или `отложено`/`отклонено` с причиной).
- Приоритет: P1 / P2 / P3.

## Сводка
| ID | Кратко | Тип | Приоритет | Статус |
|----|--------|-----|-----------|--------|

## Пункты
```

Дальше цикл ведёт `cycle-run`: анализ, вопросы, макеты, автономная разработка, слияние.
