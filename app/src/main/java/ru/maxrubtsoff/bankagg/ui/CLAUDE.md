# Правила слоя `ui` (дизайн-система «Слиток»)

Загружается, когда работаешь в `ui/**`. Эталон вида — `docs/design-system/README.md` (от корня репозитория), читай его перед правкой интерфейса. Общая карта — в корневом `CLAUDE.md`.

## Из чего собирается экран
- Только компоненты `ui/common` и токены `ui/theme` (`Slitok` — палитра, `AppTypography`, шкала сумм `Amounts`, `Motion`, `ScreenHeader`).
- Суммы — только через `MoneyText` / `AmountText` (не форматируй руками).
- Нет нужного компонента → сначала добавь его в дизайн-систему: `ui/common` + раздел в `docs/design-system/README.md` + пример в `docs/design-system/showcase.html` и в витрине `ui/showcase/ShowcaseScreen.kt`. Потом используй. Новый компонент или смена вида — через макет и согласование с пользователем (это работа агента `designer`).
- Меняешь компонент — в том же коммите обнови README, витрину и её пример.

## Выбор делается каноном, не заново (U-70)
Прежде чем собрать любой выбор или ввод, **открой таблицу компонентов в `docs/design-system/README.md` и найди подходящий там** — не по памяти и не «похоже, такого нет». Одно и то же действие выглядит одинаково на всех экранах.

| Что выбираем | Чем |
|---|---|
| Одно значение из длинного набора (банк, счёт) | `SelectRow` + шторка `*PickSheet` |
| Строка выбора внутри шторки | `SheetList` + `SheetRow` |
| Один из 2–4 путей в шторке | `TileButton` |
| Один из нескольких видимых вариантов | `SlitokChip` |
| Дата | `SlitokDatePicker` |

Чего не бывает: своей ленты банков, простыни карточек на весь экран вместо `SelectRow`, своего `Row` с `clickable` в шторке. Нужного канона в таблице действительно нет → сначала компонент в `ui/common` + раздел в README + витрина, и только через макет с согласованием.

## Чего на экранах не бывает (ловит `DesignSystemGuardTest`, частично — хук `guard.ps1`)
- Своих кнопок, полей, диалогов, переключателей, меток, `Card`.
- Hex-цветов (`Color(0x…)`) — бери токены `Slitok`.
- Ручного `fontFamily = Unbounded` — бери `AppTypography`.
`DesignSystemGuardTest` не ослаблять; исключение — только с причиной в самом тесте. (`ui/theme` и `ui/common` — сама дизайн-система, на них запрет цвета/шрифта не распространяется.)

## Тёмная тема одна
Без light/dynamic. Не возвращай `dynamicColor`.

## Реактивность
ViewModel: Flow из репозитория → `StateFlow` через `stateIn` (для `StateFlow<T?>` — `stateIn<T?>`). Никаких ручных «обновить». Экран читает состояние, VM создаётся через `ui/common/ViewModelFactory` (ветка на фичу).

## Единая механика (одинаковое — одинаково)
Переключение разделов — свайп; сортировка — кнопка направления + шторка; добавление — латунный «+» со шторкой «Со скринов / Вручную», всегда последним в правом углу строки действий раздела (`SectionActions`, не в шапке); выбор из набора — плашками; шторки — `SlitokSheet`; заголовок — `ScreenHeader`. «Назад» ведёт туда, откуда пришёл; глубже — пролёт вправо, возврат — влево. Без поясняющих подписей вида «касание — сделать то-то»: непонятно — переделать элемент.

## Анимации
Учитывают системную «Убрать анимации» (тогда мгновенно) и не задерживают действие: касание срабатывает сразу, анимация идёт параллельно. Масштаб — через `Motion`.

## Строки — по-русски
Тон «Слитка»: коротко, по делу, без канцелярита.

## Нижняя панель
Сейчас четыре вкладки: Обзор · Капитал · Платежи · Настройки. «Платежи» = «Кэшбэк · Подписки» (`ui/subscriptions`). Какие вкладки видны — решает `domain/model/Features` (под тестом), UI только читает.

Число и состав вкладок — **текущее решение дизайна, не инвариант**: редизайн (дизайн/структурный пункт) может их изменить — но только через макет и согласование с пользователем, с обновлением этого файла в том же изменении. Рядовой пункт их не трогает.
