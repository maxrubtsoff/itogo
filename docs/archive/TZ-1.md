## Ошибки

### B-1. Назад из карточки валюты уводит на «Вклады»
**Статус:** разобрано · **Приоритет:** P2 · **Экран:** Капитал → Валюта → карточка валюты

**Что видно.** В карточке валюты свайп назад или кнопка «назад» открывает «Капитал» на разделе «Вклады». Ожидается: раздел «Валюта», откуда карточку открыли.

**Причина.** `ui/capital/CapitalScreen.kt:70-72`. Раздел определяется так: `picked` (выбор пользователя) → аргумент маршрута `section` → последний запомненный. Аргумент применяется через `LaunchedEffect(sectionArg) { picked = sectionArg }`. Этот эффект срабатывает заново каждый раз, когда экран возвращается в композицию, в том числе после «назад» из карточки валюты. Если «Капитал» был открыт с Обзора тапом по строке «Вклады» (маршрут `capital?section=deposits`), то после возврата `picked` снова становится `deposits`, хотя пользователь уже переключился на «Валюту». То же при входе через нижнюю панель: `openTab` восстанавливает сохранённую запись маршрута вместе со старым аргументом.

**Что сделать.** UI, без схемы БД.
- Применять аргумент маршрута один раз на запись: запоминать применённое значение в `rememberSaveable` и не перезаписывать выбор пользователя при повторном входе в композицию.
- Если делаем вместе с F-4, состояние раздела живёт в `PagerState` (он сохраняется), и аргумент только задаёт стартовую страницу.

**Как проверить (B-1).** На эмуляторе:
1. Обзор → тап «Вклады» → переключить на «Валюта» → открыть валюту → назад кнопкой и свайпом: открыт раздел «Валюта».
2. То же, но с переходом на другую вкладку нижней панели и обратно на «Капитал».
3. Тап по строке на Обзоре по-прежнему открывает нужный раздел.

### B-2. Вклад удаляется одним касанием, без подтверждения и отмены
**Статус:** разобрано · **Приоритет:** P1 · **Экран:** Вклад → Изменить → значок корзины

**Что видно.** Найдено при разборе кода, не от пользователя. В `ui/deposits/DepositManualScreen.kt:75` корзина сразу вызывает `vm.delete(depositId)` и закрывает экран. Случайное касание рядом со стрелкой «назад» или с краем — и вклад пропал без возможности вернуть (кроме восстановления всей копии).

**Что сделать.** Решается вместе с U-1: удаление + снэкбар «Вклад удалён · Вернуть».

**Как проверить.** Удалить вклад → «Вернуть» → вклад на месте со всеми полями; без «Вернуть» — удалён.

## Хотелки

### F-1. Базовый кэшбэк по каждому банку вместо «на всё остальное»
**Статус:** разобрано · **Приоритет:** P2 · **Экран:** Обзор (плашка кэшбэка), виджет, вкладка «Кэшбэк»

**Зачем.** Внизу плашки сейчас: «На всё остальное — 1% · Альфа-Банк, Т-Банк». Формулировка неверная: речь о базовом кэшбэке банка, так его и называть. Базовый у банков может быть разный (Альфа 1%, Т-Банк 3%), но может и совпадать. Базовый нужно видеть всегда.

**Причина текущего вида.** `domain/model/CashbackSpotlight.kt:99`: из категорий «Базовый кэшбэк» / «Все покупки» берётся одна строка с максимальным процентом, а в ней только банки с этим максимумом (`bestBanks`). Если у Т-Банка 3%, а у Альфы 1%, Альфа вообще пропадёт из подписи. Текст подписи собирается в `CashbackCard.kt:77` и `CashbackWidget.kt:100`.

**Как будет выглядеть** (согласовано 2026-10-21)**.**
- Подпись «Базовый кэшбэк» и ряд компактных чипов «логотип + процент» по каждому банку, у которого базовый задан, по убыванию процента: `[Т] 3%  [А] 1%  [С] 1%`. Логотипы, как в строках категорий, без названий банков.
- Если у всех одинаковый: один чип с процентом и логотипами подряд: `1% [А][Т][С]`.
- Банк без указанного базового не показываем.
- Всегда виден на плашке Обзора и в виджете (на минимальном размере виджета — одна строка чипов, лишние банки сворачиваются в «+2»).
- На вкладке «Кэшбэк» базовый — самой первой строкой в плашке каждого банка (решено 2026-10-21).

**Что сделать.**
- Домен: в `CashbackSpotlight.Spotlight` заменить `footer: Row?` на `base: List<BaseRate>` (`BaseRate(bank, percent)`), по одному на банк — лучший из его категорий `base`/`all`. Функция группировки для отображения (по проценту), под тестами.
- UI: `CashbackCard` (Обзор), `CashbackWidget`, карточка банка во вкладке «Кэшбэк».
- Тесты: разные проценты, одинаковые, банк без базового, у банка и «Базовый», и «Все покупки».

**Как проверить.** Юнит-тесты `CashbackSpotlight`; на устройстве: Альфа 1% + Т-Банк 3% → два чипа; оба 1% → один.

### F-2. Резервная копия без ручных действий и технических деталей
**Статус:** разобрано · **Приоритет:** P2 · **Экран:** Настройки → Резервная копия

**Решение (2026-10-21):** делаем автокопию в файл на телефоне (вариант 2). Системную копию Android в Google-аккаунт не включаем: данные остаются только на телефоне.

**Зачем.** Сейчас копию и восстановление надо запускать вручную, а пользователь видит технические данные: имя файла, путь к «Загрузкам». Хочется, чтобы копия просто была.

**Как сейчас.** `data/backup/BackupManager` пишет JSON в «Загрузки/BankAggregator» с меткой времени в имени, только по кнопке. Экран `SettingsBackupScreen` показывает путь и имя файла. Восстановление берёт свежий файл из этой папки; после переустановки Android не даёт приложению видеть файлы, которые записала прошлая установка, поэтому нужен системный выбор файла. В манифесте `allowBackup="false"`, то есть системная копия Android выключена.

**Как обычно делают** (ресёрч по известным практикам, без внешних источников):
1. **Системная копия Android (Auto Backup).** Android раз в сутки сам сохраняет данные приложения в Google-аккаунт пользователя (до 25 МБ на приложение), при переустановке или на новом телефоне восстанавливает автоматически, без единого нажатия. С Android 9 копия шифруется на устройстве ключом, завязанным на блокировку экрана; Google её прочитать не может. Так работает большинство приложений. Минус: данные физически уходят в облако Google, хоть и зашифрованные; это расходится с принципом «данные только на телефоне».
2. **Автокопия в файл на телефоне.** Приложение само пишет копию при изменениях, держит несколько последних версий и показывает только «Копия сохранена сегодня в 14:32». Так делают офлайн-приложения для финансов и заметок. Минус: при потере телефона копия пропадает вместе с ним, а после переустановки нужен один выбор файла.
3. **Своя синхронизация с облаком (Google Drive и т.п.)** — нужен вход в аккаунт и сеть, противоречит принципам проекта. Не рассматриваем.

**Как будет выглядеть (вариант 2).**
- Копия создаётся сама: после изменения данных с задержкой ~1 минута, чтобы не писать файл на каждую операцию из уведомлений, и не чаще раза в N минут. Один «текущий» файл перезаписывается, плюс ежедневные снимки за последние 7 дней (на случай, если испорченные данные попали в копию).
- Экран копии: одна строка статуса «Копия сохранена сегодня в 14:32» и кнопка «Восстановить». Без путей, имён файлов и кнопки «Создать». В меню экрана: «Сохранить файл копии…» (системный диалог «поделиться/сохранить» — для переноса вручную).
- Восстановление: список снимков по датам человеческим языком («сегодня», «вчера», «15 октября»), тап → подтверждение → готово.
- После переустановки (база пустая) на Обзоре плашка «Восстановить данные из копии?» → системный выбор файла уже открыт на папке «Загрузки/BankAggregator». Одно касание + выбор файла.

**Что сделать.**
- data: `BackupManager` — автосохранение по сигналу изменений (Room `InvalidationTracker` или хуки репозиториев, как `onChanged` у кэшбэка), ротация снимков, фиксированные имена файлов.
- domain: правило ротации (какие снимки хранить) — чистая функция под тестом.
- UI: новый `SettingsBackupScreen`, плашка восстановления на Обзоре при пустой базе.
- `allowBackup="false"` в манифесте не меняем.

**Как проверить.** Тест ротации; на устройстве: изменить данные → через минуту статус обновился; переустановить → плашка → восстановление из выбранного файла.

### F-3. Убрать лишние надписи у наличных

- «обновлено 21.10.2026» в карточке наличных и «обновлено 21.10» под строкой «Наличные» на Обзоре. Это дата последней ручной правки суммы. Наличные сами не обновляются, подпись сбивает с толку.

**Что сделать.**

- Поле `updatedAt` в данных и бэкапе оставить: схему не трогаем, пригодится для I-3 (история капитала).

**Как проверить.** Капитал → Наличные и Обзор: надписей нет, сумма и кнопка на месте; без суммы — «сумма не задана».

### F-5. Виджет кэшбэка заполняет место при увеличении
**Статус:** разобрано · **Приоритет:** P2 · **Экран:** виджет «Кэшбэк» на рабочем столе

**Зачем.** Если растянуть виджет, под четырьмя категориями остаётся пустое место.

**Причина (подтверждена на эмуляторе).** Контейнер виджета Glance рисует не больше 10 дочерних элементов, остальные молча отбрасываются: 4 строки с отступами и подпись уже не помещались. Кроме того, `CashbackWidget` правильно считает, сколько строк влезает по высоте (`CashbackWidget.kt:113`), но берёт их из `spotlight.allRows` — это максимум 4 главные + 1 «максимум» (`CashbackSpotlight.MAIN_ROWS = 4`). Больше категорий ему просто не отдают.

Отдельно: на скриншоте нет строки «на всё остальное», хотя код виджета её рисует. Вероятно, виджет не перерисовался: он обновляется только при сохранении кэшбэка и раз в 6 часов. Проверить на устройстве; если подтвердится — обновлять виджет и при смене месяца/дня и при открытии приложения.

**Как будет выглядеть.**
- Маленький (2×1–2×2): как сейчас, 2–4 категории + строка базового (F-1).
- Средний (по высоте 3–4 клетки): все категории месяца по убыванию полезности, сколько влезает, внизу базовый кэшбэк.
- Широкий (4 клетки в ширину): две колонки категорий.
- Если категорий меньше, чем места, и уже конец месяца — блок «Следующий месяц» (если добавлен) или подсказка «Добавить кэшбэк на ноябрь».

**Что сделать.**
- Домен: `CashbackSpotlight` отдаёт полный ранжированный список (`ranked`), а не только 4+1; плашка на Обзоре берёт первые 4, виджет — сколько влезет. Тест на порядок.
- Виджет: раскладка по размеру, две колонки при ширине, базовый кэшбэк из F-1.
- Обновление виджета: при смене дня (уже есть `SystemToday`) и при открытии приложения.

**Как проверить.** Растянуть виджет по высоте и ширине: место заполняется, ничего не обрезается; на минимальном размере как сейчас.

### F-6. Облегчить раздел «Вклады»: компактный список и сортировка
**Статус:** разобрано · **Приоритет:** P2 · **Экран:** Капитал → Вклады

**Зачем.** Раздел перегружен: в шапке шесть чисел, часть дублируется («накоплено» и «доход», «вложено» и «к выдаче»), в каждой карточке шесть элементов.

**Как будет выглядеть** (согласовано 2026-10-21, макет в чате):
- **Шапка:** одна крупная сумма без подписи («Стоимость вкладов сейчас» убрать — из контекста раздела ясно). Под ней строка «+248 764 ₽ за всё время · +1 222 ₽ сегодня». «Вложено / к выдаче / доход» — по тапу на шапку, раскрываются под строкой.
- **Строка списка:** «N вкладов», справа чип сортировки и кнопка «+».
- **Список:** одна панель, строки с разделителями. В строке: логотип банка (без названия), текущая сумма, справа прирост; ниже ставка и «N дн.» до конца; тонкая полоса срока. Если у вклада есть своё название («Надёжный») — показать его мелко рядом со ставкой. Тап — карточка вклада, там все детали.
- **Сортировка** (шторка по тапу на чип): по закрытию (сначала ближайшие, по умолчанию), по открытию (сначала новые), по сумме, по приросту, по ставке, по доходу к концу срока, по банку. Повторный тап по выбранному — обратный порядок. Выбор запоминается.
- Закрытые вклады (срок прошёл) — внизу отдельной группой «Закрытые», свёрнутой.

**Что сделать.**
- Домен: `DepositSort` (enum + компаратор) — чистая функция под тестом.
- data: запоминать сортировку в `SettingsStore`.
- UI: `ui/deposits/DepositsScreen.kt` — новая шапка, список, шторка сортировки; `DepositUi` — строка.

**Как проверить.** Тест компараторов; на устройстве с 1 и с 5+ вкладами: всё влезает, сортировка переключается и переживает перезапуск, убранные цифры доступны в один тап.

### F-7. Разбивка разрядов при вводе сумм
**Статус:** разобрано · **Приоритет:** P2 · **Экран:** все поля ввода сумм

**Зачем.** При вводе «2000000» трудно считать нули: тысяча это или миллион. Нужна разбивка по три цифры прямо во время ввода: «2 000 000».

**Как будет выглядеть.** Пока вводишь, цифры сами группируются пробелами по три: `1` → `1 000` → `1 000 000`. Дробная часть после запятой не группируется: `1 234 567,89`. Курсор не прыгает, стирание работает как обычно (пробел не надо стирать отдельно). Ставки и проценты (`16,5`) не трогаем — только суммы.

**Что сделать.**
- Домен/общее: функция форматирования строки ввода с группировкой и пересчётом позиции курсора — чистая, под тестами (вставка в середину, стирание у пробела, запятая, вставка из буфера).
- UI: один общий `VisualTransformation` (отображение с пробелами, в состоянии хранятся только цифры) или общий компонент поля суммы; подключить во всех полях сумм: `CashSheet`, `FxOperationSheet`, `DepositForm`, `CashbackForm` (если там есть суммы, а не только проценты).
- `parseAmountMinor` уже игнорирует пробелы — разбор не ломается.

**Как проверить.** Тесты функции; на устройстве: ввести, вставить из буфера, стереть цифру в середине, поставить запятую — разбивка верная, курсор на месте, сохранённая сумма совпадает.

### F-8. Загрузка нескольких скринов сразу с умной группировкой
**Статус:** принято: все доработки распознавания из разбора скринов делаем · **Приоритет:** P2 · **Экран:** Кэшбэк → добавить скрин; Вклады → добавить со скрина

**Зачем.** Сейчас скрины выбираются по одному: каждый раз открыть галерею, выбрать, дождаться, повторить. Хочется выбрать сразу несколько. При этом бывает по-разному:
- несколько скринов про **один** вклад (на одном сумма и ставка, на другом даты) или про один банк кэшбэка (длинный список категорий не влез на один экран);
- несколько скринов про **разные** вклады или разные банки;
- смесь того и другого.

**Идея (на обсуждение, до макетов).** Пользователь ничего не раскладывает сам — приложение раскладывает, пользователь только поправляет.
1. Системный выбор фото с множественным выбором (`PickMultipleVisualMedia`, без разрешений на галерею).
2. Каждый скрин распознаётся как сейчас, затем приложение **группирует** их:
   - кэшбэк — по банку и месяцу: скрины одного банка склеиваются в один список, повторяющиеся категории схлопываются;
   - вклады — по банку и совпадению данных: если поля не противоречат друг другу (одна сумма, ставка, даты дополняют друг друга) — это один вклад, данные со скринов сливаются; если противоречат (две разные суммы на входе) — разные вклады.
3. Экран проверки — **одна** страница со списком карточек «что получилось»: «Т-Банк · 3 категории · 2 скрина», «Вклад Т-Банк 1 000 000 ₽ · 2 скрина», «Не распознано · 1 скрин». У каждой карточки миниатюры её скринов.
4. Исправление в одно действие: перетащить миниатюру в другую карточку («это тот же вклад») или вытащить в отдельную («это другой»); у поля, где скрины дали разные значения, — выбор из двух.
5. Одна кнопка «Сохранить всё». Для кэшбэка сохраняется вопрос «Дополнить / Заменить», если у банка уже есть кэшбэк за месяц.
6. То же при «Поделиться» несколькими скринами из галереи (U-3, `ACTION_SEND_MULTIPLE`).

**Что сделать.** _После согласования макетов._ Предварительно:
- домен: группировка распознанных скринов (кэшбэк — по банку/месяцу; вклады — по совместимости полей) и слияние данных — чистые функции под тестами; посмотреть, что уже умеет `CashbackMerge`;
- data: черновик пакета загрузки (несколько скринов → группы) до сохранения;
- UI: множественный выбор, общий экран проверки пакета для кэшбэка и вкладов.

**Решения (2026-10-21).**
- Экран проверки показывается всегда.
- Перенос скрина — тап по миниатюре → скрин крупно + шторка «Перенести в…» (другие карточки, «Отдельный вклад/банк», «Убрать скрин»). Без перетаскивания.
- Макеты показаны в чате 2026-10-21: проверка вкладов, проверка кэшбэка, шторка переноса.

### U-1. Удаление с «Вернуть» вместо диалогов подтверждения

**Что сделать.** Общий механизм: удалённая запись держится в памяти ViewModel, снэкбар «… удалён · Вернуть», по «Вернуть» запись возвращается тем же id. Применить к вкладу, валютной операции, строке и банку кэшбэка, скрину. Диалоги «Удалить скрин?» (`DepositAddScreen.kt:187`, `CashbackScreen.kt:691`) и «Удалить покупку?» (`FxOperationSheet.kt:235`) убрать. Подтверждение оставить только для восстановления из копии — оно заменяет всё.

**Как проверить.** Для каждого типа: удалить → «Вернуть» → запись на месте; удалить и подождать → удалена; итоги на Обзоре пересчитались.

### U-2. Предупреждение на Обзоре, если доступ к уведомлениям пропал

**Что сделать.** `Perms.hasNotificationAccess` проверять при `onResume` (через состояние в ViewModel), плашка на `OverviewScreen`, убрать «Проверить» в `SettingsBanksScreen.kt:79`.

**Как проверить.** Выключить доступ в системе → вернуться в приложение → плашка; включить → плашка исчезла без перезапуска.

### U-5. Размер APK: 47 МБ ассетов
**Статус:** принято · **Приоритет:** P3 · **Экран:** —

**Зачем.** В APK лежат модель для подбора категорий кэшбэка (`assets/embedder/model.onnx`, 28 МБ) и данные распознавания текста (`assets/tessdata/rus.traineddata`, 19 МБ). Каждое обновление из CI — ~50 МБ на телефон, плюс время запуска, если модель грузится сразу.

**Итог разбора (2026-10-22).** Модель подбора категорий уже квантована (int8: `MatMulInteger`/`DynamicQuantizeLinear` в файле) и грузится лениво, при первом подборе категории — выигрыша без переобучения нет. Данные Tesseract можно заменить облегчённой «fast»-версией (в разы меньше), но реальный OCR и так пропускает крупные цифры на плашках (см. F-8); ухудшать распознавание ради размера не стоит. Замена требует скачать файл модели — не делал без разрешения. Решение: оставить как есть, вернуться, если размер обновлений станет мешать.

**Что сделать (ресёрч).** Проверить: квантована ли модель (int8 обычно в ~4 раза меньше без заметной потери качества); грузится ли она лениво, только при подборе категории; есть ли более лёгкий вариант `rus.traineddata` (у Tesseract есть «fast»-версии в разы меньше). Решение — по замерам качества на текущих тестах распознавания.
