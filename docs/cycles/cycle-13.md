## Пункты

### B-79. График: вклад появляется в дату добавления, а не в дату открытия
**Тип:** ошибка. **Приоритет:** P2. **Статус:** новое.

Вклад, добавленный сегодня с датой открытия 01.06.2026, попадает на график изменения капитала точкой «сегодня»; точки на 01.06.2026 нет. Ожидание: вклад отображается на графике с даты открытия — когда он добавлен в приложение, значения не имеет.

### B-80. Скрины вкладов распознаются не полностью
**Тип:** ошибка. **Приоритет:** P1. **Статус:** новое.

Загрузка скринов карточек вклада («Вклад №1: Альфа-Банк», завершён, 650 000 ₽ → 770 191,47 ₽, 18,49 %, 07.08.2024 — 07.08.2025) даёт неполный результат:
- в большинстве случаев не распознаётся сумма при открытии;
- местами не распознаются даты периода;
- название вклада распознаётся как «Сумма при открытии вклада» (подпись поля принята за название).

Скрины — разные вёрстки одной карточки: `docs/cycles/cycle-13-shots/B-80/deposit-1..5.jpg`:
1. светлая карточка, сетка в 3 колонки, подписи «Сумма на входе / Сумма на выходе / Ставка», даты строкой ниже, цветные суммы;
2. 4 колонки в одну строку, «Сумма при открытии вклада» переносится на две строки;
3. одна колонка, суммы без пробелов-разделителей (`650000₽`);
4. одна колонка, у суммы открытия **нет подписи**;
5. одна колонка, подпись просто «Сумма».

Ожидание: все поля (название/банк, сумма открытия, сумма в конце, ставка, даты, статус) распознаются на всех пяти. Проверка — прогнать эти скрины через распознавание на эмуляторе (`device-check`).

### B-81. Подписи значимых точек на графике толстые, с толстой обводкой
**Тип:** ошибка. **Приоритет:** P2. **Статус:** новое.

Подписи сумм у значимых точек на графике изменения капитала (появились в F-49, цикл 12) по-прежнему выглядят толстыми и с толстой обводкой — «до сих пор», то есть уже замечалось. Ожидание: тонкий аккуратный текст по «Слитку», без грубого контура. Проверить на всех вкладках обзора, где есть такие подписи, и снять скрин на эмуляторе (`device-check`).

### F-51. Доступ к операциям истории: просмотр, правка, удаление, переход к уведомлению
**Тип:** хотелка, дизайн-пункт (нужны макеты). **Приоритет:** P1. **Статус:** новое.

Сейчас с операцией из истории ничего нельзя сделать — ни посмотреть подробно, ни исправить, ни удалить. Из-за этого мусор попадает на график и в капитал.

Примеры:
- **Наличные.** «Ради прикола» изменил сумму: взял 1000, вернул 1000 — на графике два изменения, хотя по сути ничего не было. Нужна возможность удалить такие изменения. Тап по операции наличных сейчас просто переводит в раздел «Наличные» — бесполезно, нужно показывать саму операцию.
- **Счета.** В истории есть операция +20,26 млн — такой не может быть (ошибка распознавания). Ни отредактировать, ни удалить, ни перейти к ней нельзя.

Хотелось бы:
- для операций по счёту — открывать снизу шторку с просмотром операции и там же править/удалять;
- из операции переходить к **уведомлению, которое её породило** (журнал);
- для остальных видов (вклады, наличные, валюта и пр.) — продумать, нужна ли та же шторка или другое поведение; для наличных — точно показывать саму операцию, а не раздел.

Учесть: после правки/удаления пересчитываются баланс, график и капитал. Связано с F-36 цикла 11 (тап по строке истории открывает объект) — это поведение пересматривается.

### U-67. Удержание на графике: операции подтягиваются сразу, график стоит на месте
**Тип:** удобство. **Приоритет:** P2. **Статус:** новое.

Сейчас при нажатии и удержании на графике (выбор точки) список операций ниже прокручивается к нужным операциям только **после отпускания** пальца — экран уезжает вниз.

Ожидание:
- прокрутка списка происходит **сразу**, пока палец ведёт по графику;
- экран не опускается к операциям — нужные операции **подтягиваются вверх**, под график;
- график изменений остаётся в поле видимости и **на месте** и при нажатии, и при отпускании пальца.

Проверить на эмуляторе (`device-check`): ведение пальцем по графику, отпускание, без скачков экрана.
