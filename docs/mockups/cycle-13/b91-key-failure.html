B-91 · Ключ данных не открылся

Сейчас при сбое Android Keystore приложение молча удаляет зашифрованную базу и запускается пустым, а первая же операция перезаписывает сегодняшнюю автокопию пустыми данными. Нужно: ничего не удалять, сказать человеку, дать вернуться к данным. Важная деталь из кода: автокопии на телефоне запечатаны ключом из того же Keystore (PhoneKeys.backupKey) — если ключ потерян совсем, они тоже не откроются. Спасают «Попробовать снова» (сбой часто временный), копия для переноса с паролем и старые незашифрованные копии.

A · Экран ключа

После входа (пин/отпечаток) вместо приложения — один спокойный экран. Файл базы не трогается. Три пути по убыванию безопасности: попробовать снова, восстановить из копии, начать заново — и тогда старый файл откладывается, а не удаляется (дальше — как в B).

Плюсы
  • Нельзя случайно продолжить на пустых данных и затереть копии.
  • Честно: видно, какие копии откроются, а какие нет — до ввода пароля.
Минусы
  • Пока экран открыт, приложение не работает (уведомления банков, пришедшие в это время, пропадут — см. B).

B · Работать дальше, данные отложены

Приложение открывается сразу на новых пустых данных и продолжает ловить уведомления. Старый файл отложен. Сверху Обзора — плашка, пока данные не вернули. После восстановления новые операции доливаются поверх копии, а не теряются.

Плюсы
  • Ни одно уведомление не теряется, пока человек разбирается.
  • Не блокирует приложение из-за, возможно, временного сбоя.
Минусы
  • Пустой капитал пугает сильнее экрана ошибки.
  • Слияние копии с новыми операциями — новая логика (дедуп по журналу).
