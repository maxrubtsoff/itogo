# Публикация: ключ подписи и сборка

Как перейти на собственный ключ публикации (F-28 цикла 6) и что уже готово в сборке.

## Что уже сделано

- **Подпись из секретов.** Release-сборка в CI подписывается ключом из секретов GitHub, если они заданы. Пока секретов нет, используется прежний `app/debug.keystore`, поэтому обновление ставится поверх, как раньше.
- **Отладочная сборка отдельно.** У debug-сборки свой идентификатор `ru.maxrubtsoff.bankagg.debug` и название «Itogo debug». Она ставится рядом с настоящим приложением и не видит его данных.
- **Номер версии растёт сам.** `versionCode` равен номеру сборки CI, `versionName` — `1.0.0` (поднимается вручную в `app/build.gradle.kts`).
- **Действия CI закреплены по коммитам**, а не по тегам: подменить их тихо нельзя.
- **R8** включён для release: код меньше и быстрее (замеры — в `docs/analysis/performance.md`).

## Как сделать ключ публикации

Делается один раз, на своём компьютере. Ключ нельзя терять и нельзя никому показывать: без него не выпустить обновление.

1. Создать ключ (нужен JDK, команда `keytool`):

   ```bash
   keytool -genkeypair -v -keystore itogo-release.keystore -alias itogo -keyalg RSA -keysize 4096 -validity 10000
   ```

   Запомнить оба пароля. Положить файл ключа и пароли в надёжное место (менеджер паролей, резервная копия). Не в репозиторий.

2. Превратить ключ в строку для секрета:

   ```bash
   base64 -w0 itogo-release.keystore > itogo-release.b64
   ```

3. В GitHub: репозиторий → Settings → Secrets and variables → Actions → New repository secret. Четыре секрета:

   | Секрет | Что положить |
   |--------|--------------|
   | `SIGNING_KEYSTORE_BASE64` | содержимое `itogo-release.b64` |
   | `SIGNING_STORE_PASSWORD` | пароль хранилища |
   | `SIGNING_KEY_ALIAS` | `itogo` |
   | `SIGNING_KEY_PASSWORD` | пароль ключа |

   После этого следующая сборка в CI подписана новым ключом.

## Переход на новый ключ без потери данных

Новый ключ — новая «печать» автора. Android не поставит приложение с новой печатью поверх старого, поэтому переход делается один раз:

1. В старом приложении: «Настройки → Резервная копия → Отправить копию» — задать пароль копии и сохранить файл (например, себе в Telegram или на Диск).
2. Удалить старое приложение.
3. Поставить сборку, подписанную новым ключом.
4. «Восстановить из копии → Из файла…», ввести пароль копии.

Дальше обновления снова ставятся поверх.

После перехода `app/debug.keystore` убирается из release-подписи, а в README и CLAUDE.md правило про «фиксированный ключ в репозитории» меняется на «ключ в секретах CI».

## RuStore: что готово в проекте

- **Артефакты CI:** `bank-aggregator` — release APK (его загружаем), `itogo-aab` — AAB про запас. Для AAB RuStore просит передать ему ключ подписи, а с APK ключ остаётся только у вас. Перед первой загрузкой сверьтесь с консолью.
- **Подпись publish:** `signingConfigs.publish` берёт ключ из секретов CI (см. выше).
- **Политика:** `docs/privacy.md`, публикуется через GitHub Pages (`docs/_config.yml`).
- **Версия:** `versionName` 1.0.0, `versionCode` = номер сборки CI.
- **Проверено в release:**
  - не debuggable, включены R8 и сжатие ресурсов, есть `baseline-prof.txt`;
  - `allowBackup="false"`;
  - разрешения только INTERNET, ACCESS_NETWORK_STATE, POST_NOTIFICATIONS; нет SMS и `QUERY_ALL_PACKAGES`, банки перечислены в `<queries>`;
  - слушатель уведомлений защищён `BIND_NOTIFICATION_LISTENER_SERVICE` (`exported="false"`: к нему привязывается только система, этого достаточно);
  - `Log.v/d/i` вырезаются R8, `Log.w` без данных пользователя остаётся;
  - targetSdk 34, minSdk 26, `applicationId` `ru.maxrubtsoff.bankagg`.

## RuStore: что сделать пользователю

- [ ] **Ключ публикации** и 4 секрета CI (раздел «Как сделать ключ публикации»). Ключ и пароли: в менеджер паролей и офлайн-копия файла. Потеря ключа означает, что обновление больше не выпустить.
- [ ] **Перейти на новую подпись на своём телефоне** (раздел «Переход на новый ключ»: копия, удалить, поставить, восстановить). Текущий `app/debug.keystore` лежит в публичном репозитории, поэтому в RuStore выходить можно только с ключом publish: иначе «обновление» подпишет кто угодно. Менять `debug.keystore` мимо этого документа нельзя. Тем, кто ставил приложение со старой подписью, Android не даст обновиться поверх: понадобится переустановка с копией данных.
- [ ] **Аккаунт разработчика RuStore** (вход через VK ID). Для бесплатного приложения хватает физлица; ИП или самозанятость нужны для платных. Сверить с условиями консоли.
- [ ] **Включить GitHub Pages:** Settings, Pages, Source: Deploy from a branch, Branch `main`, папка `/docs`. Политика откроется по адресу `https://<логин>.github.io/<репозиторий>/privacy`. Эту ссылку вписать в карточку.
- [ ] **Карточка:** название «Itogo», короткое и полное описание (основа: вводные слайды), категория «Финансы», возрастной рейтинг по анкете, иконка 512×512 PNG, 2-3 вертикальных скриншота (Обзор, Капитал, Платежи, виджет; на демо-данных или со скрытыми суммами), ссылка на политику.
- [ ] **Загрузить APK** из артефакта `bank-aggregator` сборки `main`. Перед этим проверить подпись: `apksigner verify --print-certs app-release.apk` должен показать новый сертификат, а не `Android Debug`.
- [ ] **Ответы модерации:**
  - Доступ к уведомлениям: читаются только уведомления выбранных банковских приложений, чтобы записать операцию и остаток. Ничего не отправляется, доступ можно выключить в настройках Android.
  - Интернет: только публичные курсы ЦБ РФ.
  - Показ уведомлений: собственные напоминания приложения.
