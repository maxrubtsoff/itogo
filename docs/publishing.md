# Публикация: ключ подписи и сборка

Как перейти на собственный ключ публикации (F-28 цикла 6) и что уже готово в сборке.

## Что уже сделано

- **Подпись из секретов.** Release-сборка в CI подписывается ключом из секретов GitHub, если они заданы. Пока секретов нет, используется прежний `app/debug.keystore`, поэтому обновление ставится поверх, как раньше.
- **Отладочная сборка отдельно.** У debug-сборки свой идентификатор `ru.maxrubtsoff.bankagg.debug` и название «Itogo debug». Она ставится рядом с настоящим приложением и не видит его данных.
- **Номер версии растёт сам.** `versionCode` равен номеру сборки CI, `versionName` — `0.6.<номер>`.
- **Действия CI закреплены по коммитам**, а не по тегам: подменить их тихо нельзя.
- **R8** включён для release: код меньше и быстрее (замеры — в `docs/analysis/performance.md`).

## Как сделать ключ публикации

Делается один раз, на своём компьютере. Ключ нельзя терять и нельзя никому показывать: без него не выпустить обновление.

1. Создать ключ (нужен JDK, команда `keytool`):

   ```bash
   keytool -genkeypair -v -keystore itogo-release.keystore -alias itogo -keyalg RSA -keysize 4096 -validity 10000
   ```

   Запомнить оба пароля. Положить файл ключа и пароли в надёжное место (менеджер паролей, резервная копия). Не в репозиторий.

2. Превратить ключ в строку для секрета:

   ```bash
   base64 -w0 itogo-release.keystore > itogo-release.b64
   ```

3. В GitHub: репозиторий → Settings → Secrets and variables → Actions → New repository secret. Четыре секрета:

   | Секрет | Что положить |
   |--------|--------------|
   | `SIGNING_KEYSTORE_BASE64` | содержимое `itogo-release.b64` |
   | `SIGNING_STORE_PASSWORD` | пароль хранилища |
   | `SIGNING_KEY_ALIAS` | `itogo` |
   | `SIGNING_KEY_PASSWORD` | пароль ключа |

   После этого следующая сборка в CI подписана новым ключом.

## Переход на новый ключ без потери данных

Новый ключ — новая «печать» автора. Android не поставит приложение с новой печатью поверх старого, поэтому переход делается один раз:

1. В старом приложении: «Настройки → Резервная копия → Отправить копию» — задать пароль копии и сохранить файл (например, себе в Telegram или на Диск).
2. Удалить старое приложение.
3. Поставить сборку, подписанную новым ключом.
4. «Восстановить из копии → Из файла…», ввести пароль копии.

Дальше обновления снова ставятся поверх.

После перехода `app/debug.keystore` убирается из release-подписи, а в README и CLAUDE.md правило про «фиксированный ключ в репозитории» меняется на «ключ в секретах CI».

## Что ещё нужно для RuStore

- Аккаунт разработчика RuStore.
- Политика конфиденциальности: всё хранится на телефоне, в сеть приложение ходит только за курсами ЦБ, данные пользователя никуда не уходят.
- Объяснение доступа к уведомлениям: приложение читает уведомления банков, чтобы видеть операции и остатки.
- Скриншоты и описание (вводные слайды F-29 подойдут как основа).
