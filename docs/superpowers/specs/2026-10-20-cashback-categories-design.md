# Кэшбэк: категории без справочника, умное сопоставление, определение банка

Дата: 2026-10-20. Статус: согласовано с Максимом.

## Зачем

Распознавание кэшбэка по скрину сейчас теряет строки. Банки пишут категории по-своему
(«Медицинские услуги», «Связь, интернет и ТВ», «Lamoda»), а `CategoryMatcher` сравнивает
только по написанию (Левенштейн) со справочником. «Медицинские услуги» не совпадает со
«Здоровьем», строка приходит с пустой категорией, а распознанный текст в UI выбрасывается
(`CashbackViewModel.loadShotDraft` кладёт `""`). Пользователь видит пустое поле без подсказки.

Вторая боль: справочник категорий, который нужно вести руками, плодит дубли и не
подходит для брендовых предложений (Lamoda — не категория, но кэшбэк на неё бывает).

Цель — **простое взаимодействие**: загрузил скрин, строки заполнились сами, руками только
поправить. Сложность (синонимы, модель, группы) живёт под капотом и в UI не видна.

## Цели

1. Строки со скрина автоматически получают общее название, если оно есть по смыслу:
   «Медицинские услуги», «Медицина», «Здоровье и медицина» → «Здоровье»;
   «Связь, интернет и ТВ» → «Связь и интернет».
2. Бренды и всё, что не сводится к общему названию, сохраняются текстом как есть
   («Lamoda»), без создания категорий.
3. Похожее у разных банков складывается в одну группу (для «лучшего кэшбэка» и плашки).
4. Ручной ввод и скрин используют одно и то же окно выбора.
5. Банк со скрина определяется по имени файла и тексту; если не определён — не выбран.

## Не цели

- Плашка на главной («любимые» → «важные», запасной базовый кэшбэк). Это **следующий
  отдельный проект**, здесь не трогаем, кроме минимума, чтобы она продолжила работать.
- Большая мультимодальная модель (Gemini Nano, Gemma и т. п.), сетевые вызовы.
- Определение банка по фирменному цвету экрана — отложено (решение Claude: у Максима
  Samsung, имя файла решает задачу; цвет — потом, если понадобится).
- Миграция старых данных. Приложение в разработке, `fallbackToDestructiveMigration()`
  допустимо, старые кэшбэк-строки и справочник можно потерять.

## Анти-цели (провал, даже если «работает»)

- UI с пояснениями «было / заменено / вернуть» на каждой строке — Максим явно отверг как
  слишком сложное.
- Дубли в данных из-за разного написания одного и того же.
- Что-либо, требующее интернета или платного сервиса.
- Бизнес-логика сопоставления в Compose-функциях.

## Модель данных (решено)

### Группы вместо справочника

- Пользовательский справочник категорий (`categories` таблица, `CategoryRepository.add`,
  «Своя» категория, `AddCategoryDialog`) **убирается**.
- Вводится фиксированный набор **групп**, зашитый в код домена. Основа — текущий
  `CategoryPresets.all` (22 пункта, у каждого `iconKey`). Состав и названия можно
  уточнить (например, разделить «Здоровье» и «Аптеки» уже разделены — оставить), это
  решает билдер.
- Каждая группа имеет: стабильный ключ (`key`), отображаемое название, `iconKey`,
  список синонимов (см. ниже).
- Иконка строки кэшбэка = иконка её группы. Отдельного выбора иконки нет.

### Строка кэшбэка

`CashbackItem` хранит:
- `category: String` — отображаемый текст (название группы или текст как есть);
- новое поле `groupKey: String` — ключ группы (для группировки, иконки, сравнения);
  для нераспознанного — ключ группы «Другое».

`CashbackSummary.bestPerCategory` и `homeCard` группируют по `groupKey`, а не по
нормализованному тексту. Отображаемое имя строки в сводке — название группы
(решение Claude; для группы «Другое» — исходный текст, чтобы «Lamoda» не схлопнулась
с другим «Другим»: для `other` ключ группировки = нормализованный текст).

Room: поднять `version`, убрать `CategoryEntity`/`CategoryDao` (или оставить таблицу
без использования — на усмотрение билдера), добавить колонку `groupKey` в кэшбэк.
`BackupManager` — убрать экспорт/импорт справочника, добавить `groupKey`.

### Избранное (временно, до проекта плашки)

`favorite` сейчас живёт в справочнике. Переносится на группы: множество ключей
избранных групп хранится в `SettingsStore`. `FavoriteCategoriesScreen` показывает
группы. Плашка `homeCard` фильтрует по `groupKey` из этого множества. Больше ничего
в логике плашки не меняем.

## Сопоставление текста с группой (решено)

Чистая доменная функция, например `CategoryResolver.resolve(text): Resolution`, где
`Resolution` = { `groupKey`, `displayName`, `confidence`, `kind` }. Шаги по порядку,
первый уверенный результат побеждает:

1. **Нормализация** — существующая `CategoryMatcher.normalize`.
2. **Точное / синонимы.** Словарь синонимов на каждую группу (домен, под тестами):
   «медицина», «медицинские услуги», «клиники», «стоматология» → Здоровье;
   «фастфуд», «кофейни» → Кафе; «связь», «мобильная связь», «интернет», «тв» → Связь и
   интернет; и т. д. Наполнение словаря — билдер, по типовым формулировкам Сбера,
   Т-Банка, Альфы, Яндекса, МТС, Ozon (минимум 3–5 синонимов на группу).
3. **Разбиение фразы.** Режем по запятым, «и», «/», «&»; если какая-то часть совпала по
   шагу 2 — берём эту группу. «Связь, интернет и ТВ» → «Связь и интернет».
4. **Модель смысловой близости** (см. ниже): эмбеддинг текста против эмбеддингов
   названий и синонимов групп. Два порога:
   - **высокий** — текст по смыслу и есть эта категория → подменяем на название группы;
   - **средний** — текст похож на группу, но, возможно, это бренд/партнёр → название
     оставляем как есть, от группы берём только иконку.
   Текст, похожий на собственное имя (латиница одним-двумя словами, слова с заглавной не
   из словаря синонимов), **никогда не подменяется** — только иконка.
5. **Ничего не подошло** — `displayName` = текст как есть, `groupKey` = «Другое».
6. **Мусор** — после удаления процента осталось меньше 3 букв → строка без категории
   («Выберите…»). (Решение Claude.)

**Списка брендов нет и вести его не нужно** — ни пользователю, ни в коде. Бренды и
партнёры (Lamoda — только пример) распознаются как «не категория» по правилам выше и
сохраняются текстом со скрина.

Правило подмены названия:
- шаги 2, 3 и 4 (высокий порог) → `displayName` = название группы (подменяем молча);
- шаг 4 (средний порог), 5 и имена собственные → `displayName` = исходный текст.

**Ключ идентичности строки** (решение Claude): если `displayName` = название группы —
ключ = `groupKey`; если это текст как есть (бренд, «Другое») — ключ = `groupKey` +
нормализованный текст. Так «Lamoda 10%» и «Одежда 5%» на одном скрине — две разные строки,
и в сводке «Одежда» не покажет 10%, которые действуют только в Lamoda. Бренд берёт от
группы только иконку. Этот же ключ — для дедупликации строк скрина (максимум процента
побеждает), `bestPerCategory` и `homeCard`. Избранная группа включает только строки с
названием группы, не бренды.

### Модель смысловой близости (решено: добавляем)

- Офлайн, бесплатная, зашита в APK, понимает русский. Максим согласен на +30–120 МБ.
- Живёт за доменным портом (интерфейс в `domain/repository`, например `TextEmbedder`),
  реализация в `data/`. Домен остаётся чистым; в тестах — фейковый эмбеддер.
- Если модель не загрузилась — шаг 5 пропускается, остальное работает.
- Выбор модели и рантайма — за билдером. Рекомендация Claude: `cointegrated/rubert-tiny2`
  (≈29 млн параметров, русский, ≈30–45 МБ в int8) через ONNX Runtime Android, WordPiece-
  токенайзер на Kotlin. Альтернатива — `multilingual-e5-small` (тяжелее, ≈120 МБ int8).
  Эмбеддинги групп/синонимов можно посчитать один раз при старте и закешировать.
- Порог косинуса подбирается на тестовом наборе формулировок; при сомнении — не
  подставлять (консервативно, как весь парсер).

## Определение банка по скрину (решено)

Порядок:
1. **Имя файла.** Получить `DISPLAY_NAME` у URI из Photo Picker
   (`OpenableColumns.DISPLAY_NAME`). Samsung One UI дописывает имя приложения
   (`Screenshot_20261020_120000_Sberbank.jpg`), Xiaomi — пакет (`..._ru.sberbankmobile.jpg`).
   Чистая доменная функция `guessBankFromFileName(name)`: ищет пакеты из
   `BankBrand.packages` и названия приложений банков. Реальные имена с Samsung Максима
   (суффикс после даты и времени): `Screenshot_20261020_141742_Ozon.jpg` → Ozon Банк,
   `Screenshot_20261020_141731_T-Bank.jpg` → Т-Банк,
   `Screenshot_20261020_141737_Yandex Pay.jpg` → Яндекс Пэй (с пробелом). Сбер, Альфа и МТС
   имя приложения в скрин не пишут — для них только текст на скрине. Имя файла сохранять в `CashbackShot` (новое поле), чтобы
   распознавание было повторяемым.
   Не проверено, что Photo Picker отдаёт настоящее имя файла (на части версий Android
   может вернуть сгенерированное вида `1000012345.jpg`). Первым делом проверить на
   Samsung Максима. Если имени нет — шаг пропускается; Photo Picker не меняем и
   разрешений (`READ_MEDIA_IMAGES`) не добавляем (решение Claude, по правилам приватности).
2. **Текст на скрине** — существующий `CashbackParser.guessBank`.
3. Не определён → банк **не выбран**.

## UI (решено)

### Экран после скрина
- Сверху фото (как сейчас), затем банк, затем строки.
- Строка: иконка группы, название (`displayName`), процент, удалить. **Без** подписей
  «было / заменено / вернуть».
- Строка без категории — «Выберите…» (как сейчас).
- Банк: если определён — выбран; если нет — ни один не выбран.
- «Сохранить»: если банк не выбран — показать выбор банка (диалог/шит со списком банков),
  после выбора продолжить.
- **Несколько скринов одного банка за месяц** (категории часто не влезают на один экран).
  Если у банка за этот месяц уже есть строки и набор новых строк отличается (по ключу
  идентичности, см. выше) — диалог вместо «Заменить кэшбэк?» с двумя действиями:
  - **«Дополнить»** — добавить новые строки к сохранённым; строки с тем же ключом
    обновляют процент;
  - **«Заменить»** — заменить кэшбэк банка за месяц новыми строками (как сейчас).
  Если у банка ещё ничего нет — сохранить без диалога. Если набор ключей совпадает —
  обновить проценты без диалога (решение Claude). Логика слияния — чистая доменная
  функция под тестами.

### Окно выбора (одно на скрин и ручной ввод)
Заменяет `CategoryPickerDialog`.
- Поле поиска. Со скрина — предзаполнено исходным текстом строки (OCR). При ручном
  вводе — пусто.
- Блок «Похоже»: результаты `CategoryResolver` по тексту поля (1–3 лучших группы).
- Пункт «Оставить «<текст>»» — сохранить текст как есть; группа — что дал резолвер
  (по модели), иначе «Другое».
- Ниже — все группы списком с иконками (фильтруются по вводу).
- «Готово» на клавиатуре = «Оставить как есть».
- Кнопки «Своя категория» больше нет.

Для этого строке черновика нужен исходный текст OCR (`DraftLine.rawText`), сейчас он
теряется в `loadShotDraft`.

### Ручной ввод
- Тот же `ManualCashbackDialog`, банк по умолчанию **не выбран** (сейчас — первый в
  каталоге); при «Сохранить» без банка — выбор банка, как на экране скрина.
- Тап по категории — окно выбора с пустым поиском.

### Редактирование (решено)
Список кэшбэка за месяц сгруппирован по банкам (`BankCashbackPanel`).
- **Крестики удаления со строк списка убираются.**
- **Тап по строке** — правка одной строки: тот же `ManualCashbackDialog`, предзаполненный
  (банк, название, процент), плюс кнопка «Удалить» внутри диалога.
- **Иконка-карандаш в шапке банка** (только иконка, без текста «Изменить») — экран правки
  всего банка за месяц. Это тот же экран, что после скрина, но без фото: строки банка,
  удаление строки крестиком, «Добавить строку», «Сохранить» (заменяет кэшбэк банка за месяц).
- «Добавить строку» на этом экране и на экране скрина: добавляет строку и **сразу
  открывает то же окно выбора**, что и ручной ввод; после выбора фокус на процент.
  Банк не спрашивается — он уже известен. (Решение Claude: отдельный диалог внутри
  экрана с собственной кнопкой «Сохранить» дал бы двойное сохранение.)
- **Скрин после «Сохранить» удаляется** (запись `CashbackShot` и файл картинки). Сейчас он
  остаётся в ленте скринов, и его можно зачем-то открыть и сохранить повторно.
- **Скрин распознаётся один раз.** Результат распознавания (черновые строки, банк, имя
  файла) сохраняется вместе со скрином; открытие несохранённого скрина показывает этот
  черновик, а не перезапускает OCR (сейчас `loadShotDraft` всегда распознаёт заново).

Макеты, согласованные в чате: экран «только итог» + окно выбора с поиском, «Похоже»,
«Оставить», «Все». Стиль — «Слиток» (`Panel`, палитра `Slitok`, шрифты из `typography`).

## Ограничения

Всё из `CLAUDE.md`: DDD-слои, домен без Android, `Money` для сумм (тут проценты —
`Double`, как сейчас), Room + KSP, ручной DI в `AppContainer`, офлайн, русский UI,
не трогать подпись. Работа и пуш прямо в `main`.

## Тесты (минимум)

- `CategoryResolver`: синонимы, разбиение фраз, два порога модели, имена собственные, «Другое», мусор; модель —
  через фейковый эмбеддер.
- `guessBankFromFileName`: форматы Samsung, Xiaomi, Pixel (без приложения → null).
- `CashbackParser` и `CashbackSummary` — обновить под `groupKey`.
- Набор реальных формулировок банков как фикстура (что должно стать чем). Реальных
  скринов пока нет: собрать формулировки по публичным условиям банков; порог модели
  ставить консервативно и уточнить, когда Максим даст скрины.
- Слияние «Дополнить / Заменить».

## Оставлено билдеру

Точный состав и наполнение синонимов, модель и рантайм эмбеддингов, порог,
форма выбора банка (диалог или шит), судьба таблицы `categories`, разбиение на коммиты.
