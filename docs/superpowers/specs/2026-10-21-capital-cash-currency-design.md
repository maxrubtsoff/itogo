# ТЗ: капитал из четырёх источников, наличные, валюта, новая навигация, умный кэшбэк, вёрстка сумм

Дата: 2026-10-21. Статус: все развилки согласованы с Максимом. Решения Claude — в разделе 15.
Ветка: `spec/cash-currency`. Реализацию, по CLAUDE.md, ведём прямо в `main` поэтапно (раздел 14).

---

## 0. Зачем

Сейчас «Общий капитал» на Обзоре складывается из рублёвых счетов и вкладов. У Максима есть
ещё **наличные рубли дома** и **купленная валюта**, и их в приложении нет. Поэтому реальный
капитал приложение не показывает.

Попутно накопились неудобства:
- вкладка «Счета» почти ничего не даёт;
- кэшбэк спрятан за карточкой;
- «любимые» категории кэшбэка не работают: любимой категории в этом месяце может просто не быть;
- суммы рвутся по строкам (одинокий «₽» на второй строке);
- приложение поворачивается при наклоне телефона.

Аудит кода нашёл ещё несколько ошибок в расчётах и надёжности данных, их тоже чиним (раздел 11).

## 1. Цели

1. **Наличные.** Одна сумма в рублях, которую Максим правит одним касанием.
2. **Валюта.** История покупок и продаж (у каждой свой курс). Пересчёт в рубли по курсу ЦБ на
   сегодня. Прирост в рублях: по каждой валюте, по каждой покупке и в целом.
3. **Курсы ЦБ РФ.** Автоматически раз в день, кнопка «↻» и дата курса на экране.
4. **Общий капитал** складывается из четырёх частей: счета, вклады, валюта и наличные. Что
   входит в итог, Максим решает сам. Деления на «личные / ИП» больше нет: все счета Максима
   его собственные.
5. **BSB Bank (Беларусь)** — новый банк в каталоге. Его валютные счета — это «валюта на
   счёте», они входят в часть «Валюта» (раздел 8.5).
6. **Новая навигация:** Обзор · Кэшбэк · Капитал · Настройки.
7. **Умная плашка кэшбэка.** Приложение само решает, что важно. Без «любимых».
8. **Ни одна сумма и ни одна подпись не рвётся по строкам**, включая экран шириной 360dp.
9. **Только портретная ориентация.**
10. **Исправления из аудита** (раздел 11).

## 2. Не цели

- Брокерские счета, акции, крипта, металлы.
- Курсы коммерческих банков, биржевой курс, курсы внутри дня. Только официальный курс ЦБ.
- Несколько «мест» хранения наличных (сейф, кошелёк). Одна сумма.
- Покупки и продажи валюты на банковском счёте. **История операций «Купил / Продал» — это
  только наличная валюта дома** (решение Максима). Валюта на счетах (BSB и любые другие
  не-рублёвые счета из уведомлений) берётся остатком из уведомлений, без истории покупок.
  Две разные группы, пересечения нет, двойного учёта нет. В форме покупки подпись:
  «наличная валюта».
- Прирост по валюте на счетах: себестоимость неизвестна, показываем только стоимость в ₽.
- Деление счетов на «личные / ИП»: убирается из UI и из капитала.
- Налоги, комиссии обменников отдельной строкой. Они уже учтены в курсе или в сумме в ₽.
- Ранжирование кэшбэка по реальным тратам (нужен разбор магазинов из уведомлений) — потом.
- Миграции Room без потери данных. Остаётся `fallbackToDestructiveMigration()`, данные
  восстановимы из бэкапа.

## 3. Анти-цели (провал, даже если «работает»)

- Хоть одна сумма где-либо рвётся по строкам, или «₽» обрезан.
- В сеть уходит что-то кроме запроса курсов ЦБ. Любые данные пользователя наружу — провал.
- Курс не обновился, а пользователь этого не видит (нет даты курса или предупреждения).
- Один и тот же рубль посчитан в капитале дважды. Например, вклад, который уже вернулся на счёт.
- Нижняя панель длиннее четырёх вкладок.
- Плашка кэшбэка снова просит что-то «отметить».
- Бизнес-логика (капитал, позиции валюты, ранжирование кэшбэка) в Compose-функциях.

## 4. Ограничения

- Всё из CLAUDE.md: DDD-слои, `Money` в копейках, Room + KSP, ручной DI, «Слиток», русский UI,
  тёмная тема, подпись не трогаем.
- **Сеть — только для курсов ЦБ.** Принцип «полностью локально» меняется на «данные локально,
  в сеть ходим только за публичными курсами ЦБ, без данных пользователя». Обновить
  CLAUDE.md (разделы 1 и 9) и README. Разрешение `INTERNET` уже есть в манифесте.
- **Без новых сетевых библиотек.** `HttpURLConnection` + `javax.xml.parsers` (есть и на
  Android, и в JVM-тестах). Retrofit, OkHttp, Ktor не тащим.

## 6. Обзор

```
Обзор
┌──────────────────────────────────────┐
│ Общий капитал                     ⚙ │
│ 4 700 300 ₽            (FitText)     │
│ ▓▓▓▓▓▓▓▓▒▒▒▒▒▒▒░░░░▪                │  ← полоса состава
│ ● Счета             1 900 000 ₽   › │
│ ● Вклады            2 100 000 ₽   › │
│     +84 210 ₽ накоплено             │
│ ● Валюта              862 700 ₽   › │
│     наличные +23 500 ₽ · +3,4%      │
│ ○ Наличные            112 000 ₽   › │  ← выключено, серое
│     не в итоге                      │
└──────────────────────────────────────┘
┌ Кэшбэк · октябрь              все › ┐
│ (умная плашка, раздел 9)             │
└──────────────────────────────────────┘
```

- **Герой.** Подпись «Общий капитал», сумма одной строкой с автоуменьшением шрифта
  (раздел 10), справа иконка ⚙ (`Tune`).
- Убираются:
  - строка «включая вклады · …»;
  - плашки «Личные» / «ИП / бизнес». Их заменяет состав.
- **Полоса состава.** Горизонтальная полоса из сегментов, пропорциональных долям частей,
  которые входят в итог. Цвет сегмента = цвет точки строки.
- **Строки состава.** Порядок фиксированный: Счета, Вклады, Валюта, Наличные.
  - Показываются только части, где есть данные (сумма ≠ 0 или есть записи).
  - Вторая строка у строки состава:
    - Вклады: «+X ₽ накоплено» (мята);
    - Валюта: «наличные +X ₽ · +Y%» (мята или коралл по знаку). Прирост только по наличной
      валюте, у валюты на счетах себестоимости нет;
    - Наличные: «обновлено dd.MM».
  - Выключенная часть: серая точка-кольцо, сумма цветом `Faint`, подпись «не в итоге». В полосу
    не входит.
  - Тап по строке открывает «Капитал» на этом разделе.
- **Шторка ⚙** (`ModalBottomSheet` в стиле «Слитка»). Заголовок «В общий капитал входит».
  Четыре переключателя по частям, по умолчанию все включены. Действует сразу, без кнопки
  «Сохранить». Хранится в `SettingsStore`, попадает в бэкап.
- **Блок «По банкам» с Обзора уходит.** Разбивку по банкам показывает раздел «Счета» в Капитале.
  (Решение Claude, см. раздел 15.)
- **Пустое состояние** (нет ничего): одна панель «Пока пусто» и три действия: «Выбрать банки»,
  «Добавить вклад», «Добавить валюту».
- Если для какой-то валюты нет курса ни разу (первый запуск офлайн): часть «Валюта» считается
  без неё, под строкой подпись «нет курса для CNY — ↻».

## 7. Вкладка «Капитал»

Сверху заголовок «Капитал». Под ним переключатель разделов в стиле нижней панели (латунная
«пилюля» на активном): **Счета · Вклады · Валюта · Наличные**. Последний открытый раздел
запоминается (`rememberSaveable` + `SettingsStore`), но параметр `section` из маршрута важнее.

### 7.1 Счета
- Содержимое бывшей вкладки «Счета» и блока «По банкам»: группы по банку (иконка, название).
  Внутри банка его счета с балансом. Пометок «Личный / ИП» нет. Бизнес-банки (Альфа-Бизнес,
  Т-Бизнес) остаются в каталоге как обычные банки.
- Здесь только **рублёвые** счета. Не-рублёвые счета (BSB и любые другие) показываются в
  разделе «Валюта» (8.5).
- Итог раздела сверху — одна сумма.
- Правка счетов (переименовать, скрыть) — не цель этого ТЗ.

### 7.2 Вклады
- Текущий `DepositsScreen` без изменений логики, кроме:
  - правок вёрстки (раздел 10);
  - **завершённых вкладов** (раздел 7.5);
  - исправлений расчётов (раздел 11.2).
- Строку «+X накоплено · сегодня +Y» заменить двумя колонками-статами, как `Stat`:
  «Накоплено» / «За сегодня». Подпись мелким шрифтом сверху, значение `FitText` снизу,
  колонки равной ширины, выравнивание по левому краю.

### 7.3 Валюта
```
Валюта в рублях
862 700 ₽
наличные: +23 500 ₽ · +3,4% за всё время   ← мята/коралл
курс ЦБ на 21.10 · ↻                     ← мелко; при устаревании — латунь/предупреждение

Наличными
┌──────────────────────────────────────┐
│ $  Доллар США            81 200 ₽   │
│    1 000 $ · ср. 76,50     +4 700 ₽ │
├──────────────────────────────────────┤
│ €  Евро                 619 100 ₽   │
│    6 500 € · ср. 92,10    +18 800 ₽ │
└──────────────────────────────────────┘
[ + Купил ]   [ − Продал ]

На счетах
┌──────────────────────────────────────┐
│ [BSB] Доллар США        162 400 ₽   │
│       2 000 $                       │
├──────────────────────────────────────┤
│ [BSB] Белорусский рубль   ...  ₽    │
│       ... Br                        │
└──────────────────────────────────────┘
```
- **Шапка.**
  - Вся валюта (наличная + на счетах) в рублях по курсу ЦБ на сегодня.
  - Нереализованный прирост в ₽ и % по наличной валюте (раздел 8.3), плюс зафиксированная
    прибыль, если были продажи: «зафиксировано +1 200 ₽».
  - Строка «курс ЦБ на dd.MM · ↻». Тап по «↻» обновляет курсы, во время запроса крутится
    индикатор. Ошибку показывать коротким снекбаром: «Нет связи с ЦБ, курс от 18.10».
- **Карточка валюты.** Символ в круге, название по-русски, справа стоимость в ₽. Вторая строка:
  остаток в валюте, средний курс покупки, прирост в ₽. Тап открывает экран валюты.
- **Экран валюты.**
  - Герой: стоимость в ₽, прирост.
  - Плитки: «Остаток», «Средний курс», «Курс ЦБ сегодня», «Зафиксировано».
  - **История операций** по убыванию даты:
    - «Купил · 21.10.2025 · 1 000 $ по 76,50 = 76 500 ₽», справа «сейчас +4 700 ₽»;
    - «Продал · 05.03.2026 · 300 $ по 84,00 = 25 200 ₽», справа «прибыль +2 250 ₽».
  - Тап по операции открывает правку, там же «Удалить» с подтверждением.
- **Кнопки «Купил» и «Продал»** открывают форму операции (раздел 8.4). «Продал» неактивна, если
  валюты нет.
- **Группа «На счетах».**
  - Все не-рублёвые счета из уведомлений: иконка банка, название валюты, справа стоимость в
    ₽, ниже остаток в валюте.
  - Прироста нет. Тапа нет (детали счёта не цель).
  - Группа скрыта, если таких счетов нет.
- **Пустое состояние** (ни наличной валюты, ни счетов): «Валюты пока нет» и кнопка «Добавить
  покупку».

### 7.4 Наличные
```
Наличные
112 000 ₽
обновлено 12.10.2026
[ Изменить сумму ]
```
- **Одна сумма в рублях и дата последнего изменения.** Тап по сумме или по кнопке открывает
  шторку с полем суммы, где уже стоит текущее значение. Поле в фокусе, цифровая клавиатура
  открыта сразу.
- В шторке три режима-чипа: **Задать** (по умолчанию) / **+ Добавить** / **− Взять**. В режимах
  «+» и «−» под полем живой результат: «станет 117 000 ₽». Сумма не может стать
  отрицательной.
- Кнопка «Сохранить». История изменений не хранится. В модели держим только текущую сумму и
  `updatedAt`.

### 7.5 Завершённые вклады
- Вклад **активен**, если `сегодня ≤ endDate`. В день окончания вклад ещё активен: банки
  закрывают вклады обычно вечером (решение Максима). Это включает вклады с будущей датой
  начала: деньги уже ушли с карты.
- **Вклад с будущей датой начала:**
  - в капитале и в сводке считается по сумме на входе;
  - накоплено 0, «за сегодня» 0;
  - в списке пометка «начнётся dd.MM».
- **Со следующего дня после `endDate` вклад не входит в капитал** (деньги уже на счёте, иначе
  двойной учёт). Он уходит в свёрнутую группу внизу раздела: «Завершённые · N · доход
  +X ₽».
- Сводка раздела (стоимость, вложено, к выдаче, доход, за сегодня) считается **только по
  активным**.
- Кнопки «Продлить» нет. Новые вклады заводятся вручную или по скрину, как сейчас (решение
  Максима).

## 8. Валюта: модель, курсы, расчёт

### 8.1 Справочник валют
- В домене зашит статический список валют ЦБ (около 40 штук: код ISO, название по-русски,
  символ, если он общеизвестен). Например:
  - USD «Доллар США» $;
  - EUR «Евро» €;
  - CNY «Китайский юань» ¥;
  - GBP £, CHF, JPY, TRY, KZT, AED, BYN, AMD, GEL, THB, INR и т. д.

  Источник списка — ответ `XML_daily.asp`. Билдер выгружает его один раз при написании кода.
- В выборе валюты сверху стоят уже используемые валюты, затем USD, EUR, CNY, затем остальные
  по алфавиту. Есть поиск по коду и названию. В форме по умолчанию выбрана последняя
  использованная валюта.
- `Money.format` получает символы из этого справочника (сейчас там только RUB/USD/EUR). Если
  символа нет, выводится код: «1 000 KZT».

### 8.2 Курсы ЦБ
- **Источник:**
  - курс на сегодня: `https://www.cbr.ru/scripts/XML_daily.asp?date_req=dd/MM/yyyy`;
  - курс на дату покупки: тот же запрос с нужной датой.

  Нюансы ответа:
  - кодировка windows-1251;
  - десятичная запятая;
  - у части валют `Nominal` ≠ 1 (100 JPY, 10 CNY в прошлом), курс за единицу = `Value / Nominal`
    (или поле `VunitRate`, если есть).

  Ставить заголовок `User-Agent`, таймаут 10 с.
- Дату в запросе всегда передавать явно: сегодня по Москве. Иначе после обеда ЦБ отдаёт курс
  на завтра.
- **Хранение:**
  - таблица `fx_rates(code, date, rubPerUnitMicro: Long)`, где курс × 1 000 000 и
    PK `(code, date)`;
  - время последней успешной загрузки и время последней попытки — в `SettingsStore`.
- **Когда обновлять:**
  - при старте приложения или возврате в него (`onResume`), если курс на сегодня ещё не
    получен и с последней попытки прошло больше часа. Тихо, без индикатора на весь экран;
  - по «↻» — всегда.

  WorkManager не нужен.
- **Какой курс брать «на сегодня»:** курс с максимальной датой ≤ сегодня. В выходные ЦБ курс
  не ставит, берётся субботний.
- **Устаревание:** если дата курса старше 3 дней, строка «курс ЦБ на …» окрашивается латунью и
  получает «обновить». Расчёты при этом идут по последнему известному курсу.
- Без сети приложение работает полностью, только курс не свежий.

### 8.3 Расчёт (чистый домен, под тестами)
Новые модели:
- `FxOperation(id, currency, kind: BUY|SELL, date: LocalDate, amountMinor: Long, rubMinor: Long, createdAt)`.
  Сумма в валюте в сотых, рубли в копейках. **Курс не хранится, он вычисляется:**
  `rub / amount`. Так нет расхождения на округлении. Показывать курс с двумя знаками, если
  он точный, иначе с четырьмя.
- `FxRate(currency, date, rubPerUnitMicro: Long)`.
- Все умножения и деления курса — через `BigDecimal` с `HALF_UP` до копейки.

Позиция по валюте (`FxPortfolio.position(ops, rateToday)`). Метод **средней цены**, операции
идут по `(date, createdAt)`:
- **BUY:** `qty += amount`, `cost += rub`.
- **SELL:**
  - `avg = cost / qty`, `costOut = avg × amount`;
  - `realized += rub − costOut`;
  - `qty −= amount`, `cost −= costOut`.
- Итог позиции:
  - `value = qty × rateToday`;
  - `unrealized = value − cost`, `unrealizedPct = unrealized / cost`;
  - `avgRate = cost / qty`.
- Прирост «за всё время» в шапке = `unrealized`. Отдельно показывается `realized`, если ≠ 0.
- Прирост по строке покупки в истории (информативно): `amount × rateToday − rub`.
- **Валидация истории — доменная функция `FxPortfolio.validate(ops)`.** Она проходит всю
  историю валюты и находит первую продажу, на которую не хватает остатка. Вызывается при
  любом изменении: сохранении, правке даты или суммы, удалении.
  - Если изменение ломает историю, оно **блокируется** с понятным текстом:
    - при сохранении продажи: «На 05.03 было только 400 $»;
    - при удалении или уменьшении покупки: «Без этой покупки не хватит валюты на продажу
      05.03».
  - Отрицательный остаток в данных невозможен. Деления на ноль в `avgRate` нет: при
    `qty = 0` средний курс не показывается.
- Не-рублёвые **банковские счета** из уведомлений не участвуют в позициях. Их остаток
  конвертируется по `rateToday` и идёт в часть «Валюта», группа «На счетах» (8.5).

### 8.4 Форма операции (шторка)
- Заголовок «Покупка валюты» или «Продажа валюты». Поля:
  - **Валюта.** Чип с кодом, тап открывает выбор (8.1).
  - **Сколько.** Сумма в валюте, цифровая клавиатура, фокус сразу.
  - **Дата.** По умолчанию сегодня, будущие даты недоступны.
  - **Курс** ↔ **Отдал ₽** (для продажи «Получил ₽»). Пользователь заполняет любое из двух,
    второе пересчитывается живьём. Последнее изменённое поле главное. Если правишь «Сколько»,
    пересчитывается неглавное.
- Под полем курса чип **«ЦБ на 21.10: 81,20»**. Тап подставляет курс. Чип грузится по дате
  (из кеша `fx_rates`, иначе запрос). Без сети чип скрыт, это не ошибка.
- Кнопка «Сохранить» активна, когда заполнены сумма и курс (или ₽), а для продажи ещё и
  проходит валидация остатка.
- Пример из запроса: 1000 $, 21.10, курс 76,5. Сохраняется `rub = 76 500,00 ₽`, в истории
  «Купил · 21.10 · 1 000 $ по 76,50 = 76 500 ₽».

### 8.5 BSB Bank и валюта на счетах
- **Новый банк в `BankBrand`:** `BSB("bsb", "BSB Bank", …, isBusiness = false, packages)`.
  Цвет фирменный (выбирает билдер). Пакет приложения добавить в `<queries>` манифеста (по
  правилам CLAUDE.md).
- **Имя пакета:** `by.bank.bsb.mobile` (подтвердил Максим с телефона).
- **Порядок для BSB:**
  1. Добавить банк с пакетом.
  2. Максим выбирает BSB в «Банках».
  3. Журнал перехвата сохраняет и нераспознанные уведомления (`CapturedEvent.parsed = false`).
     Через несколько дней Максим присылает выгрузку.
  4. По реальным текстам пишутся правила и тесты парсера. До этого BSB-уведомления только
     копятся в журнале, балансы не считаются.
- **Валюты парсера.** Сейчас парсер знает только RUB/USD/EUR и **по умолчанию ставит RUB**.
  Белорусские рубли (BYN, «Br», «бел. руб.») посчитались бы как российские. Нужно:
  - распознавать код или символ валюты рядом с суммой по справочнику 8.1 (BYN, USD, EUR,
    RUB, CNY…);
  - для BSB **не** подставлять RUB по умолчанию: валюта не найдена — операция не
    распознана (`null`), как требует принцип консервативного парсера.
- **Куда идут деньги.** Любой счёт с валютой ≠ RUB (BSB и любой другой банк) входит в часть
  «Валюта», группу «На счетах», по курсу ЦБ (BYN у ЦБ есть). В «Счета» он не входит.
- `AccountKind` (PERSONAL/BUSINESS) больше нигде не показывается и не влияет на капитал. Если
  после правок он нигде не нужен, удалить вместе с колонкой `kind` (Room всё равно
  поднимается до v8).

## 9. Умная плашка кэшбэка

Заменяет «любимые». Логика — чистая функция домена `CashbackSpotlight.build(...)`, под
тестами.

**Вход:** строки кэшбэка текущего месяца, есть ли строки на следующий месяц, сегодняшняя
дата.

**Ранжирование:**
- У каждой группы (`CategoryGroups`) есть зашитый в домене **вес повседневности**:
  - 1.0 — Супермаркеты;
  - 0.9 — Кафе, АЗС;
  - 0.8 — Аптеки, Онлайн-покупки;
  - 0.7 — Рестораны, Такси;
  - 0.6 — Транспорт;
  - 0.5 — Связь и интернет, Здоровье, Одежда;
  - 0.4 — Красота, Дом и ремонт, Электроника, Животные, Дети, Спорт, Развлечения;
  - 0.3 — Путешествия;
  - 0.2 — Другое и бренды.

  Точные числа подбирает билдер, порядок — как здесь.
- Для каждой группы берётся лучший процент месяца (`CashbackSummary.byCategory`).
  `score = вес × процент`.
- **Основные строки:** топ-4 по `score`, без «Базовый кэшбэк» и «Все покупки».
- **«Максимум месяца»:** самая высокая ставка месяца, если она ≥ 10% и не попала в топ-4.
  Может быть и брендом («Lamoda 15%»). Одна строка с меткой «максимум».
- **Подвал:** «На всё остальное — 1,5% · Т-Банк». Это лучшая из групп «Базовый кэшбэк» и
  «Все покупки», если она есть.

**Строка:** иконка группы, название, процент (латунь, `1,5%` через запятую), до 3 иконок
банков с этим процентом и «+N».

**Подсказки** (вместо строк или над ними):
- нет кэшбэка на текущий месяц: «Кэшбэк на октябрь не добавлен», кнопка «Добавить скрин»;
- с 25-го числа, если нет строк на следующий месяц: чип «Выбрать кэшбэк на ноябрь». Ведёт во
  вкладку «Кэшбэк» на следующий месяц.

**Тап** по плашке открывает вкладку «Кэшбэк».

**Убрать:**
- `FavoriteCategoriesScreen`;
- звезду на экране кэшбэка;
- `favoriteGroups` из `SettingsRepository`/`SettingsStore`;
- `CashbackSummary.homeCard`;
- мёртвые `bestPerCategory`/`top` (и тесты на них заменить тестами `Spotlight`).

Импорт старого бэкапа поле `favoriteGroups` молча игнорирует.

**Виджет** показывает тот же порядок (`Spotlight`, все строки, сколько влезет по высоте) и
подвал «на всё остальное». Месяц пересчитывается при каждой отрисовке.

Обновление виджета:
- `updatePeriodMillis` = 6 ч;
- плюс обновление при смене месяца и после сохранения кэшбэка;
- а не на каждый `onResume`.

Иконки банков уменьшать до размера строки, чтобы не упереться в лимит `RemoteViews`.

## 10. Вёрстка сумм и переносы

**Корень проблемы:** `Money.format` ставит обычный пробел перед «₽». Это единственное место,
где длинная сумма может переломиться. Плюс крупные суммы (Unbounded 34sp) не влезают в
288dp.

**Правила для всего приложения:**
1. **`Money.format`.**
   - Между числом и символом — неразрывный пробел U+00A0. Разряды уже неразрывные (ICU), это
     закрепить тестом.
   - Добавить `formatNumber()` без символа. На него перевести `amountDigits` в `DepositUi`:
     сейчас он режет по ASCII-пробелу и сломается.
   - Тест: в результате нет U+0020.
2. **Любой `Text` с суммой:** `maxLines = 1`, `softWrap = false`. Либо автоуменьшение
   (`FitText`), либо гарантированно достаточная ширина. Обрезка «₽» без эллипсиса
   запрещена.
3. **`FitText` обобщить в `AmountText`.**
   - Параметры `maxSize` и `minSize`. Для героев 34 → 20sp, для плиток 18 → 12sp.
   - Подбор размера за один проход через `TextMeasurer`, а не уменьшением ×0.92 за несколько
     кадров (сейчас размер видно «прыгает»).
   - Все герои: Обзор, Вклады, вклад, Валюта, валюта, Наличные.
4. **Строка «подпись + сумма».**
   - Подпись: `weight(1f)`, `maxLines = 1`, `overflow = Ellipsis`.
   - Сумма: без веса, `AmountText`.
   - Выравнивание по базовой линии (`alignByBaseline`), если шрифты разные.
5. **Составные строки** («+X ₽ · накоплено за N дней», «X → Y»): один `Text` с
   `buildAnnotatedString`. Вокруг « · » и внутри сумм — неразрывные пробелы. Если не влезает,
   переносить по заранее выбранной точке, а не по букве.
6. **Короткие предлоги и союзы** («в», «к», «с», «у», «о», «и», «а», «на», «по», «за»)
   приклеивать к следующему слову неразрывным пробелом. Нужна утилита `ru.nbsp()` в `ui/common`
   для строк с подстановками. Плюс `LineBreak.Paragraph` (и `Hyphens.None`) в стилях
   `body*`/`label*` в `Type.kt`.
7. **Проценты везде через запятую:** «1,5%». `formatPercent` в `CashbackCard` сейчас даёт
   «1.5%».

**Известные места, обязательно проверить** (из аудита):
- `OverviewScreen` — герой, плашки, `BrandRow`;
- `AccountsScreen` — строка счёта;
- `DepositsScreen`:
  - `HeroSummary`;
  - строка «накоплено · сегодня», которую заменяют статы 7.2;
  - `DepositCard`: сумма + «накоплено», «X → Y»;
- `DepositDetailScreen`: `Hero`, подпись «за N дней», `GrowthCard`, `Tile` (сейчас «₽»
  молча обрезается), `Fact`;
- `DepositForm`: `ComputedExitRow`, `MethodPicker` («Капитализация» в ~104dp);
- `DepositAddScreen:244`;
- `CashbackCard`, `CashbackScreen:323`.

**Приёмка:** на экране 360dp, при шрифте системы 100% и 115%, с суммами вида
`99 999 999,99 ₽` и длинными названиями банков/вкладов:
- нигде нет одинокого символа или буквы на строке;
- нет обрезанного «₽»;
- нет «прыгающего» размера.

## 11. Исправления из аудита

### 11.1 Надёжность данных
1. **Импорт бэкапа** — в `db.withTransaction`. Порядок:
   - сначала разобрать весь файл в память;
   - при любой ошибке ничего не трогать и показать «Файл повреждён, данные не изменены»;
   - только потом очистить таблицы и вставить данные.

   `FORMAT_VERSION` читать:
   - версия новее поддерживаемой — отказ с текстом «Копия из более новой версии
     приложения»;
   - версия старше — недостающие поля заполнить значениями по умолчанию.
2. **Текст диалога восстановления.** Перечислять всё, что заменяется: «счета, операции,
   вклады, валюта, наличные, кэшбэк и настройки».
3. **Восстановление после переустановки.** Сейчас Android 11+ не видит чужой (прошлой
   установки) файл в «Загрузках» и пишет «Копия не найдена». Если файл не найден через
   MediaStore, предложить выбрать файл системным диалогом (`OpenDocument`). Это одно
   касание и только в этом случае.
4. **Баланс счёта** (`LedgerRepositoryImpl.upsertAccountBalance`):
   - чтение-изменение-запись в транзакции;
   - обработку уведомлений сериализовать (`Mutex` в `RecordNotification`);
   - запись события и операции — в одной транзакции, чтобы дедуп не блокировал повтор
     после сбоя.
5. **Название счёта при обновлении баланса не затирать**: обновлять баланс, а не делать
   REPLACE всей строки.
6. **Дедуп уведомлений:**
   - игнорировать group-summary (`FLAG_GROUP_SUMMARY`);
   - хеш считать от `(pkg, нормализованный текст, сумма, баланс)` с окном ±2 минуты, а не от
     минутной корзины.
7. **OCR-модель:**
   - копировать во временный файл и переименовывать;
   - проверять размер, а не `length > 0`;
   - синхронизировать;
   - не переинициализировать на каждый `recognize`.
8. **`OnnxTextEmbedder`:** один сбой не должен навсегда выключать модель на всю сессию.
   Повтор при следующем вызове, но не чаще раза в минуту.
9. **Скоуп слушателя** уведомлений отменять в `onListenerDisconnected`/`onDestroy`.
10. **Редакторы кэшбэка** (`ShotPreviewScreen`, `BankCashbackEditScreen`): состояние в
    `rememberSaveable`/ViewModel. Двойное «назад» при сохранении закрыть флагом.
11. **Правка строки кэшбэка** не должна плодить дубль при смене банка или категории (дедуп по
    identity при upsert).

### 11.2 Расчёты и даты
1. **Капитал — в домене.** `CapitalCalculator.compute(...) → CapitalSnapshot`: части, итог,
   доли для полосы, нехватка курсов. Use-case `GetCapital` собирает потоки. Из
   `OverviewScreen` расчёты уходят. Тесты:
   - включение и выключение частей;
   - валютные счета по курсу;
   - завершённые вклады не входят;
   - нет курса.
2. **«Сегодня» живое.** Источник даты в домене — интерфейс `Today: Flow<LocalDate>`.
   Реализация в data: тикает в полночь (по таймеру до следующей полуночи, плюс
   `ACTION_DATE_CHANGED`/`TIME_SET`). Через него пересчитываются:
   - вклады;
   - капитал;
   - месяц кэшбэка (`CashbackViewModel.currentMonthItems` сейчас фиксирует месяц при создании
     VM);
   - плашка.
3. **`DepositMath.monthly`** теряет день на стыке месяцев. Конец месяца считать как 1-е число
   следующего (не включая), ограничив `endDate`. Тест: сумма месяцев = `totalIncome`.
4. **`DepositMath.summary`, «за сегодня»:**
   - только активные вклады;
   - реальное начисление за сегодняшний день (`accruedAt(today+1) − accruedAt(today)`), а не
     среднее за срок. Для капитализации это разные числа.
5. **`stateOf`:** последний день месяца ещё не PAST.
6. **`MonthlyBars`:** окно из 12 месяцев вокруг текущего, а не последние 12 месяцев срока.
7. **`ratePercent`:** показывать ставку с двумя знаками, если они есть («19,25%»).
8. **`DepositFormState.isValid`:** ставка не обязательна, если указана сумма на выходе.
9. **`parseRubles`:** понимать U+202F, считать в `Long` без `Double`.
10. **`DepositParser.AMOUNT`:** в классе символов потерян NBSP (там два ASCII-пробела). Вернуть
    `  `, в `PERCENT` тоже.
11. **`DepositsViewModel`:** `projection(d)` не пересчитывать на каждой рекомпозиции, считать во
    VM.

## 15. Решения Claude (проверь при чтении)

1. Блок «По банкам» уходит с Обзора в раздел «Счета» Капитала. На Обзоре остаются только
   состав и кэшбэк.
2. На Обзоре показываются только части, где есть данные. Пустые части доступны во вкладке
   «Капитал».
3. Наличные: одна сумма без истории изменений. В шторке режимы «Задать / + Добавить /
   − Взять».
4. В операции валюты хранятся сумма в валюте и сумма в рублях, курс вычисляется. Учёт по
   средней цене.
5. Справочник валют зашит в код (список ЦБ). Сеть для справочника не нужна.
6. Курс «на сегодня» — последний известный с датой ≤ сегодня. Предупреждение, если старше
   3 дней.
7. Валюта на счетах (BSB) показывается без прироста: себестоимость неизвестна. Любой
   не-рублёвый счёт, не только BSB, идёт в «Валюту», а не в «Счета».
8. Веса повседневности категорий кэшбэка зашиты в домене. Порог «максимума месяца» — 10%.
9. Новые цвета частей: `Sky` для валюты и `Sand` для наличных.
10. Дедуп уведомлений по сумме и балансу с окном ±2 минуты. Окно уточняется по реальным
    примерам.
11. Вклад с будущей датой начала: в капитале по сумме на входе, без начислений.
12. Правка истории валюты, которая ломает более позднюю продажу, блокируется, а не
    исправляется автоматически.
